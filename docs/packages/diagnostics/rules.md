The engine implements exactly six rules. `DIAGNOSTIC_RULES` exports their ids,
labels, categories and default severities.

| Rule id | Category | Status | Severity | Trigger |
| --- | --- | --- | --- | --- |
| `n-plus-one-queries` | `database` | `possible` | `warning` | One normalized SQL shape repeats at least `diagnostics.repeatedQueryMin` times (default 5) in a request trace. |
| `slow-request` | `performance` | `observed` | `warning` | A request root exceeds `slowRequestMs` (default 500 ms). |
| `slow-span` | `performance` | `observed` | `warning` | A non-root span's self time exceeds its category threshold while the request itself is not already reported as slow. |
| `repeated-external-http` | `http` | `possible` | `warning` | One normalized outbound endpoint repeats at least `diagnostics.repeatedHttpMin` times (default 3) in one trace. |
| `error-fingerprint` | `errors` | `observed` | `error` | A single or repeated request error grouped by canonical route and normalized signature. |
| `server-error-response` | `errors` | `observed` | `error` | A request root returns 5xx without a correlated non-control-flow error record. |

## N+1 queries

- SQL is fingerprinted by normalized shape. Literal values and id-like path
  segments do not create a new shape.
- A finding aggregates matching traces by canonical Next.js route.
- Bind parameters are never available, so the engine cannot prove a loop.
- A batched query can still repeat for unrelated reasons.

## Slow requests

- The measurement is the request root duration, not the sum of spans.
- Findings group by method and canonical route.
- The engine attributes self time to the deepest measured spans and names the
  dominant contributor. Self time subtracts the union of direct child intervals;
  it attributes measured time and does not prove causality.
- Parent duration already includes child work. Never add overlapping spans.

## Slow spans

- Evaluated only when the enclosing request is below `slowRequestMs`; this
  avoids double-reporting a slow request and its child.
- Thresholds are category-specific: `databaseMs`, `httpMs`, `customMs`,
  `frameworkMs`, `otherMs`.
- A span can be slow because of child work, queueing, a cold start or the
  measured operation itself.
- Framework spans are evidence of Next.js work, not a root cause.

## Repeated external HTTP

- Only outbound HTTP client spans are considered.
- Query values, fragments and credentials are removed; id-like path segments are
  normalized.
- Cache status and same-app/external origin may be reported as evidence.
- Repeated calls can be intentional retries or independent requests. The rule
  cannot distinguish them.

## Error fingerprints

- The normalized error signature is route-independent, but findings group by
  canonical route so the same failure in different routes stays separate.
- The same message and stack shape can merge different causes; different shapes
  can split one cause.
- Next.js not-found, redirect and HTTP-error fallback control-flow errors are
  excluded.
- A single error is still reported; `errorGroupMin` controls when a group is
  labeled repeated.

## Server error responses

- Reports only that the request root returned 5xx without a correlated
  non-control-flow error.
- The app may have returned the status intentionally, the error hook may not
  have run, or the error record may have aged out.
- The status is proven; the cause is not.

## Detached traces

Request-level rules require an attributable request root. Spans without one,
and spans whose parent is missing, are excluded and noted in the sample
integrity metadata instead of being guessed into a request.

## Thresholds

All thresholds come from `stacknext.config.json` `diagnostics`. `enabled: false`
returns an empty report, not an error. `maxFindings` caps the report after all
rules run.
