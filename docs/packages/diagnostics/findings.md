## Finding

Each `DiagnosticFinding` includes:

- `id` — deterministic `diag-...` reference for the current sample;
- `ruleId`, `category`, `severity`, `status`;
- `title`, `summary`, `detail`;
- `route`, `method`, `firstSeen`, `lastSeen`;
- `fingerprint`;
- `affectedTraceCount`, `traceIds`;
- `evidence`;
- `verification[]` and `limitations[]`.

Ids are deterministic references, not credentials. A finding can disappear when
the underlying evidence ages out of the retention window.

## Evidence

Evidence is bounded and re-sanitized before it is returned. Fields may include:

- `measurements` — labels, values and units;
- `spans` — name, ids, duration, self duration, category, Next.js phase;
- `contributors` — self-time labels and phases;
- `traces` — trace id, occurrence count, duration and dominant contributor;
- `queries` — database system, operation, nullable duration, redacted SQL
  preview;
- `errors` — name, message, ids, route/render context and timestamp.

## List and filters

```ts
listDiagnosticFindings(report, {
  category: 'performance',
  severity: 'warning',
  status: 'observed',
  ruleId: 'slow-request',
  route: '/api/orders',
  traceId: '...',
  since: Date.now() - 60_000,
  until: Date.now(),
  q: 'orders',
  limit: 50,
  offset: 0,
})
```

- `limit` is clamped to 1–200, default 50.
- `route` is a case-insensitive substring match.
- `q` searches title, summary, detail, fingerprint, route and rule id.
- `since`/`until` are epoch milliseconds.

The response includes `items`, `total`, `limit`, `offset`, `counts`, `sample`,
`notes`, `limitations`, `engineVersion` and `ruleSetVersion`. `total` counts all
matching findings; `items` is the current page.

## Detail

`getDiagnosticDetail(report, id, snapshot)` returns
`{ finding, trace }` or `null`. The trace is a bounded context: span count,
errors, queries and missing parents. Use the collector trace API for the full
tree when it is truncated.

`diagnosticOverview(report, topLimit = 5)` returns counts, sample metadata and
the top findings for dashboards and MCP summaries.

## Status semantics

| Status | Meaning |
| --- | --- |
| `observed` | A measurement or status was directly established. |
| `possible` | The pattern is consistent with a problem but not proven. |
| `insufficient-evidence` | The sample cannot support a conclusion. |

`possible` and `observed` never mean "confirmed root cause". See the repository
the repository `docs/limitations.md` for the full boundary.
