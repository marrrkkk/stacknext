`@stacknext/next` reads environment variables supplied by `stacknext dev`. The
application does not import `stacknext.config.json` directly; the CLI resolves
the config and exports the relevant values to the child process.

## Environment variables

| Variable | Default | Behavior |
| --- | --- | --- |
| `STACKNEXT_COLLECTOR_URL` | none | Required for tracing. Must be loopback. |
| `STACKNEXT_TOKEN` | none | Required for tracing. At least 16 characters. |
| `STACKNEXT_PROJECT_NAME` | project name | Reported to the collector. |
| `STACKNEXT_SERVICE_NAME` | project or `next-app` | OTel service name. |
| `STACKNEXT_NEXT_VERSION` | none | Used for environment checks. |
| `STACKNEXT_CAPTURE_FETCH` | `1` | `0` drops `AppRender.fetch` spans. |
| `STACKNEXT_CAPTURE_ERRORS` | `1` | `0` makes `onRequestError` a no-op. |
| `STACKNEXT_DEBUG` | unset | `1` enables debug logs. |
| `NEXT_OTEL_VERBOSE` | unset | `1` enables the documented Next.js verbose span set. |

`stacknext dev` sets these from `stacknext.config.json`:
`instrumentation.captureFetch` → `STACKNEXT_CAPTURE_FETCH`,
`instrumentation.captureErrors` → `STACKNEXT_CAPTURE_ERRORS`,
`instrumentation.verbose` → `NEXT_OTEL_VERBOSE`.

An explicit environment value wins. For example, `NEXT_OTEL_VERBOSE=0` disables
verbose tracing even when the config says `"verbose": true`.

## Register options vs environment

Options passed to `registerStackNext()` take precedence for that call:
`collectorUrl`, `serviceName`, `projectName`, `nextVersion`, `captureFetch` and
`enabled`. The transport itself still requires a valid token and loopback URL.

## Verbose tracing

`NEXT_OTEL_VERBOSE=1` adds documented Next.js span types. It:

- increases stored span volume and dev-server work;
- can shorten the effective retention of older events when capacity is reached;
- does **not** enable body, header, cookie, query-value or SQL-parameter
  capture.

Use `stacknext coverage` or `get_project_summary` to see whether verbose
evidence is present. Unknown span types are retained as evidence instead of
being mapped to a guessed feature.

## What cannot be enabled

The config schema rejects:

- `privacy.captureHeaders`;
- `privacy.captureRequestBodies`;
- `privacy.captureSqlParameters`;
- `privacy.redactSensitiveData: false`.

There are no environment variables that bypass these rules.
