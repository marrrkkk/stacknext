No Drizzle queries appear

1. Confirm `createStackNextDrizzleLogger()` is passed to the same Drizzle client
   that serves requests.
2. Confirm the app is running under `stacknext dev`, which supplies the
   transport environment.
3. Make a request that actually executes a query.
4. Run `stacknext coverage`; `database` evidence should become observed.
5. Check `stacknext doctor` for adapter/config warnings.

## Queries appear without a trace

The adapter records trace/span ids only when a valid OpenTelemetry context is
active. Queries from scripts, workers or background jobs may have no request
root. They are still stored, but they are not attributed to a request.

## Duration is null

Expected. Drizzle's logger does not expose duration. StackNext stores `null` and
sets `db.duration.measured: false`.

Do not treat `null` as zero, and do not compare Drizzle and Prisma durations.

## SQL is redacted or truncated

SQL passes through `redactSql` and is capped at 20,000 characters. Bind
parameters are not included, so a value passed as `?` or `$1` cannot leak.

## The adapter throws?

It should not. `logQuery` catches sink errors and forwards them to `onError` if
provided. If an error escapes, check the Drizzle logger contract and the
`enqueueDatabaseQuery` implementation supplied through `options.transport`.

## Verify

```bash
stacknext status --json
stacknext coverage --json
stacknext diagnose --category database
```
