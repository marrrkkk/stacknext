`@stacknext/core/snapshots` implements the snapshot format used by the CLI,
collector and dashboard. A snapshot is a versioned copy of one in-memory sample
written under `.stacknext/snapshots`. It is never replayed into the live store.

## Payload

```ts
import {
  createSnapshotPayload,
  saveSnapshot,
  loadSnapshotPayload,
  listSnapshots,
  removeSnapshot,
  snapshotExport,
  importSnapshot,
  createSnapshotView,
} from '@stacknext/core/snapshots'
```

`SnapshotPayload` contains:

- `format: 'stacknext-snapshot'` and `version: 1`;
- `id`, `createdAt`, `source`, `projectName`, `collectorVersion`, `label?`;
- the resolved `config`;
- `sample` (`firstEventTime`, `lastEventTime`, `retentionMs`);
- redacted `spans`, `errors`, `databaseQueries`;
- `stats` and `limitations`.

`source` is `manual`, `exit`, `error` or `import`.

## Creating and saving

```ts
const payload = createSnapshotPayload({
  store,
  source: 'manual',
  projectName: 'my-app',
  collectorVersion: '<installed-version>',
  config,
  label: 'before refactor',
})

const summary = await saveSnapshot(projectDir, payload)
```

`saveSnapshot()` validates the payload, creates private directories and writes
atomically. Files use mode `0600`; `.stacknext` uses `0700`. The default cap is
64 MiB (`SNAPSHOT_MAX_BYTES`) and oversized saves fail instead of truncating.

## Reading and listing

- `loadSnapshotPayload(projectDir, id)` validates the id and the stored schema.
- `loadSnapshotSummary(projectDir, id)` reads the small summary record.
- `listSnapshots(projectDir, { limit, offset })` returns a page plus an
  `invalid` count. Invalid records stay visible as a count, not repaired.
- `listAllSnapshots(projectDir)` returns every valid summary.

Snapshot ids match `snap-<16 hex>`.

## Import and export

`snapshotExport(payload)` converts a snapshot to the `ExportResponse` shape used
by `stacknext export`. `importSnapshot(projectDir, contents, { maxBytes, label })`
accepts a snapshot payload or export file, re-normalizes and re-redacts it, and
writes a new `import` snapshot. Unknown formats, malformed JSON and oversized
files are rejected.

## Automatic snapshots

`rotateAutomaticSnapshots(projectDir, keep)` only considers `exit` and `error`
sources. Manual and imported snapshots are never rotated. The collector calls it
with `snapshots.autoKeep`, which defaults to 10.

## Detached views

`createSnapshotView(payload)` returns a `TelemetryStore` pinned to the save
time, with a widened retention window so old records remain readable. It carries
no live diagnostics or coverage and never mutates the live store.

The collector caches at most three detached views and invalidates them by file
`mtimeMs`. Editing or replacing snapshot files outside StackNext is unsupported.

## Limits

- A snapshot has no diagnostics, coverage or live updates.
- Automatic exit snapshots require a graceful shutdown and a non-empty sample.
- Error snapshots fire on the first error and then respect a 60-second cooldown.
- A crash, `SIGKILL` or full disk can skip an automatic save.
- Snapshots are local files. Review them before sharing, as with any export.
