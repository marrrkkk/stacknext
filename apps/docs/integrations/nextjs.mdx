StackNext uses the documented Next.js `instrumentation.ts` hook. It does not
patch Next.js internals and does not read `NEXT_PRIVATE_*` variables.

## Registration path

1. `stacknext dev` starts the collector and the project's `dev` script.
2. Next.js loads `instrumentation.ts` and calls `register()`.
3. `registerStackNext()` checks for an existing OpenTelemetry provider.
4. StackNext attaches a span processor and exporter when it owns the provider.
5. Documented Next.js spans are normalized and sent to the loopback collector.
6. `onRequestError` sends redacted request errors.

The generated instrumentation checks `NEXT_RUNTIME === 'nodejs'` and imports
`@stacknext/next` dynamically so Edge bundles do not pull Node-only modules.
Edge instrumentation is not supported even though the import is guarded.

## What is captured

- Documented `next.*` request, route, render, fetch, action and proxy spans.
- HTTP attributes and parent ids preserved from Next.js.
- Drizzle or Prisma query events when an adapter is registered.
- Errors passed to the Next.js error hook.
- Custom spans and wrapped actions from `@stacknext/next`.

Unknown span types remain as verbose evidence. They are not mapped to guessed
semantics. See [instrumentation coverage](/instrumentation-coverage).

## Existing OpenTelemetry setup

`registerStackNext()` yields to an already-registered provider. It sends a
heartbeat with capture reported as inactive, so `stacknext status`,
`stacknext doctor` and the dashboard warn instead of showing a healthy but empty
connection. To let StackNext own tracing, remove the competing registration and
call StackNext from the existing `register()` hook:

```ts
import {
  registerStackNext,
  onRequestError as stackNextOnRequestError,
} from '@stacknext/next'

export async function register() {
  // Keep your existing monitoring setup.
  await registerStackNext()
}

// Only when the file does not already export an error hook:
export const onRequestError = stackNextOnRequestError
```

If another provider owns the pipeline, StackNext cannot add a second SDK. The
heartbeat still identifies the app, but request spans are not captured; use the
existing provider's exporter or remove the conflicting registration. Verify the
state with `stacknext status`, `stacknext doctor` and `stacknext coverage`.

## Supported versions

Next.js 15 and 16 with the App Router on the Node.js runtime. The supported peer
range is `>=15.0.0 <17`. A newer major prints a warning in `stacknext init` until
it is added to the validation matrix. See [compatibility](/compatibility).
