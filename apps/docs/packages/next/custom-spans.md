StackNext exports three optional helpers from `@stacknext/next`. They use the
existing OpenTelemetry context/provider and do **not** create a second SDK.

## Async work

```ts
import { withStackNextSpan } from '@stacknext/next'

const project = await withStackNextSpan(
  'load project',
  { attributes: { 'project.id': id } },
  async (span) => {
    const project = await loadProject(id)
    span.setAttribute('project.found', project !== null)
    return project
  },
)
```

Supported signatures:

```ts
withStackNextSpan(name, fn, options?)
withStackNextSpan(name, options, fn)
```

The callback receives the active OTel `Span`. Return values and thrown errors
are preserved. By default a thrown exception is recorded unless it is a Next.js
control-flow error (`NEXT_NOT_FOUND`, `NEXT_REDIRECT*` or
`NEXT_HTTP_ERROR_FALLBACK*`). Set `recordException: false` to disable recording.

## Synchronous work

```ts
import { withStackNextSpanSync } from '@stacknext/next'

const rows = withStackNextSpanSync(
  'sqlite batch',
  { attributes: { 'batch.size': 25 } },
  () => runBatch(),
)
```

Same argument forms and error behavior as the async helper.

## Server Actions

Successful Server Actions do not reach `onRequestError`, so StackNext cannot see
them automatically. Wrap the action explicitly:

```ts
'use server'

import { withStackNextAction } from '@stacknext/next'

export async function updateProject(formData: FormData) {
  return withStackNextAction(
    'action updateProject',
    { attributes: { 'project.id': String(formData.get('id') ?? '') } },
    async () => {
      // Action body.
    },
  )
}
```

`withStackNextAction` sets `stacknext.span.kind = "action"`. It records only the
span name and attributes you pass; action arguments, `FormData` values and return
values are never captured automatically.

## Options

`StackNextManualSpanOptions`:

| Option | Type | Default | Meaning |
| --- | --- | --- | --- |
| `attributes` | `Record<string, unknown>` | none | Sanitized before enqueueing. |
| `kind` | OTel `SpanKind` | `INTERNAL` | Span kind. |
| `recordException` | boolean | `true` | Record non-control-flow errors. |

The helpers add `stacknext.manual = true` and `stacknext.span.kind` after caller
attributes so coverage cannot be spoofed.

## Attribute safety

Attributes pass through `sanitizeAttributes`: sensitive keys, headers and URL
query values are redacted. The collector applies a second pass. Do not put large
payloads or secrets in attribute values.

## What the helpers do not do

- They do not automatically trace every Server Component or Server Action.
- They do not measure work you did not wrap.
- They do not create a new provider or exporter.
- They do not capture arguments, return values or bodies.

For broader guidance see the repository's `apps/docs/custom-instrumentation.md`
and `apps/docs/server-actions.md`.
