`stacknext.config.json` lives at the root of the Next.js application.
`@stacknext/core/config-file` loads and validates it; `@stacknext/core` exports
the Zod schema and inferred types.

## Loading

```ts
import {
  CONFIG_FILE_NAME,
  configPath,
  loadConfig,
  readConfigFile,
} from '@stacknext/core/config-file'

const path = configPath(process.cwd()) // <project>/stacknext.config.json
const config = await loadConfig(process.cwd())
```

- A missing file loads the defaults.
- Invalid JSON or an invalid field throws `StackNextConfigError` with `issues`.
- The schema is strict at every level: unknown keys are rejected.

`CONFIG_FILE_NAME` is `stacknext.config.json`.

## Fields

| Field | Type / range | Meaning |
| --- | --- | --- |
| `projectName` | string, 1–200, optional | Name shown in the dashboard and records. |
| `dashboard.port` | integer, 1024–65535, default 4400 | Preferred loopback port. StackNext tries the next 25 ports if busy. |
| `collector.maxSpans` | integer, 100–100000, default 5000 | In-memory span capacity. Error and query buffers derive from it. |
| `collector.retentionMs` | integer, 30000–86400000, default 600000 | How long received telemetry stays in memory. |
| `instrumentation.verbose` | boolean, default false | Requests the documented `NEXT_OTEL_VERBOSE=1` span set. |
| `instrumentation.captureFetch` | boolean, default true | Captures Next.js `AppRender.fetch` spans. |
| `instrumentation.captureErrors` | boolean, default true | Enables the Next.js error hook. |
| `privacy.captureHeaders` | must be `false` | Header capture is not implemented. |
| `privacy.captureRequestBodies` | must be `false` | Body capture is not implemented. |
| `privacy.captureSqlParameters` | must be `false` | SQL bind capture is not implemented. |
| `privacy.redactSensitiveData` | must be `true` | Redaction cannot be disabled. |
| `database.drizzle` / `database.prisma` | boolean, default false | Setup intent for `init`/`doctor`; adapters still require registration. |
| `diagnostics.enabled` | boolean, default true | Enables the deterministic report. |
| `diagnostics.repeatedQueryMin` | integer, 2–100, default 5 | Repeated SQL shapes per trace for `n-plus-one-queries`. |
| `diagnostics.slowSpans.*` | integer, 1–600000 ms | Per-category slow-span thresholds. |
| `diagnostics.repeatedHttpMin` | integer, 2–100, default 3 | Repeated normalized endpoints per trace for `repeated-external-http`. |
| `diagnostics.errorGrouping` | boolean, default true | Enables fingerprint grouping. |
| `diagnostics.errorGroupMin` | integer, 2–100, default 2 | Occurrences before an error group is labeled repeated. |
| `diagnostics.maxFindings` | integer, 10–1000, default 100 | Hard cap per report. |
| `slowRequestMs` | integer, 1–600000, default 500 | Slow-request threshold used by CLI, dashboard and MCP. |
| `snapshots.autoOnExit` | boolean, default true | Save a snapshot on graceful `stacknext dev` exit. |
| `snapshots.autoOnError` | boolean, default true | Save a snapshot on the first error, with a 60-second cooldown. |
| `snapshots.autoKeep` | integer, 1–100, default 10 | Automatic exit/error snapshots to keep. Manual/imported are never rotated. |
| `snapshots.maxBytes` | integer, 1 MiB–256 MiB, default 64 MiB | Per-snapshot cap. Oversized saves fail instead of truncating. |

## Validation behavior

- Invalid privacy values throw, even if they are merely set to `true` and never
  used.
- `stacknext init` writes a smaller file; missing fields are filled with
  defaults when loaded.
- `stacknext doctor` reports invalid configuration with the Zod issue paths.
- The collector exports its resolved configuration through `/api/health` and
  snapshots record it with the sample.
