Run `stacknext <command> --help` for the installed version's exact flags. All
commands run from a Next.js application directory unless stated otherwise.
`stacknext --version` and `stacknext --help` are also available.

## Setup and run

### `stacknext init`

Configure a project. Writes `stacknext.config.json` and generated
`instrumentation.ts`/`.js` only when absent; never overwrites user files.

| Option | Meaning |
| --- | --- |
| `--install` | Install `@stacknext/next` with the detected package manager |
| `--agents` | Add or update the managed StackNext block in `AGENTS.md` |
| `--skip-agents` | Explicitly skip the managed block (the default) |

### `stacknext dev`

Start the loopback collector and dashboard, then run the app's `dev` script.

| Option | Meaning |
| --- | --- |
| `--open` | Open the dashboard in the default browser |
| `--quiet` | Reduce startup output |
| `--token <token>` | Use an existing token (16+ characters) |

`dev` writes `.stacknext/run.json` with mode `0600` and removes it on graceful
shutdown. Stop it with SIGINT/SIGTERM, not `SIGKILL`. Extra arguments are
forwarded to the app's dev command. It refuses to start when a live Next.js dev
server already owns the project; stop that server first.

### `stacknext status`

Print the runtime, collector connection and current counts.

| Option | Meaning |
| --- | --- |
| `--json` | Machine-readable output |

### `stacknext doctor`

Check Node.js, Next.js, the App Router, config, instrumentation, adapters,
dashboard build, runtime file permissions, collector health and first-request
capture. When another OpenTelemetry provider owns tracing, StackNext reports
capture as inactive and `doctor` fails.

| Option | Meaning |
| --- | --- |
| `--json` | Machine-readable result with `checks`, `failures`, `warnings` |

An `Agents` group also reports MCP server readiness, the installed Agent Skill,
the managed `AGENTS.md` block, local package documentation and runtime token
file permissions. Agent setup is optional, so those checks are warnings and the
token is never printed.

Exit code is `1` when a check fails.

### `stacknext uninstall`

Print a removal plan unless `--yes` is passed. See
[remove StackNext](/installation#remove-stacknext).

| Option | Meaning |
| --- | --- |
| `--yes` | Apply the plan |
| `--keep-config` | Preserve `stacknext.config.json` |
| `--remove-data` | Remove `.stacknext` saved data (refused while running) |
| `--json` | Machine-readable report |

Agent Skill directories are installed separately from the npm packages.
`uninstall` reports any it finds and points at `stacknext skill uninstall`.

## Inspect the sample

### `stacknext coverage`

Show what the current retention window observed. Evidence, not a score.

| Option | Meaning |
| --- | --- |
| `--json` | Machine-readable `CoverageReport` |

### `stacknext diagnose`

List deterministic findings or show one finding.

| Option | Meaning |
| --- | --- |
| `--id <finding-id>` | Show one finding and its related trace |
| `--trace-id <trace-id>` | Findings that reference a trace |
| `--category <category>` | `database`, `http`, `performance`, `errors`, `runtime` |
| `--severity <severity>` | `info`, `warning`, `error` |
| `--status <status>` | `observed`, `possible`, `insufficient-evidence` |
| `--rule <rule-id>` | One of the six rule ids |
| `--route <route>` | Route substring |
| `--since <time>` / `--until <time>` | ISO timestamp or epoch milliseconds |
| `--limit <n>` / `--offset <n>` | Pagination |
| `-q, --q <text>` | Search text |
| `--json` | Machine-readable output |

### `stacknext export`

| Option | Meaning |
| --- | --- |
| `-o, --output <file>` | Output path |
| `--stdout` | Write JSON to stdout |
| `--force` | Overwrite an existing output file |

Exports use mode `0600` and are redacted, but remain a full local trace dump.

## Regression

### `stacknext capture`

Run a test command and save correlated telemetry as a run.

```bash
stacknext capture --name baseline -- pnpm exec playwright test --workers=1
```

| Option | Meaning |
| --- | --- |
| `--name <name>` | Run name |
| `--project <name>` | Project name override |
| `--attach` | Require an existing `stacknext dev` collector |
| `--url <url>` | Attach to a specific loopback collector |
| `--token <token>` | Token for `--url` |
| `--json` | Machine-readable result |
| `--quiet` | Reduce output |

A successful child with incomplete telemetry exits `3`. See
[regression testing](/regression-testing).

### `stacknext runs`

| Command | Options | Purpose |
| --- | --- | --- |
| `runs list` | `--limit`, `--offset`, `--json` | List live and saved runs |
| `runs show <run-id>` | `--json` | Show one run and its samples |

### `stacknext baseline`

| Command | Options | Purpose |
| --- | --- | --- |
| `baseline save <run-id>` | `--name <name>`, `--notes <text>`, `--overwrite`, `--json` | Save a completed run |
| `baseline list` | `--limit`, `--offset`, `--json` | List baselines |
| `baseline show <baseline-id>` | `--json` | Show one baseline |
| `baseline remove <baseline-id>` | `--yes`, `--json` | Permanently remove one baseline |

`--name` is required. Only a completed run can become a baseline. A normal save
never replaces an existing baseline; `--overwrite` is an explicit storage-layer
collision override, not a replace-by-name flow.

### `stacknext compare`

```bash
stacknext compare <baseline-id> <candidate-run-id>
```

| Option | Meaning |
| --- | --- |
| `--json` | Machine-readable result |
| `--ignore-environment` | Compare despite environment differences (warning retained) |
| `--min-samples <n>` | Minimum verified samples per side (default 3) |
| `--duration-regression-pct <n>` | Default 20 |
| `--duration-regression-ms <n>` | Default 25 |
| `--duration-improvement-pct <n>` | Default 20 |
| `--duration-improvement-ms <n>` | Default 25 |
| `--count-regression-min <n>` | Default 1 |
| `--fail-on <status>` | Exit 1 for `regression`, `inconclusive` or `any` |
| `--no-save` | Do not persist the comparison |

Comparisons are report-only by default. `inconclusive` is not a pass.

| Command | Options | Purpose |

| `snapshot list` | `--limit`, `--offset`, `--json` | List snapshots |

## Agents

### `stacknext mcp`

Start the read-only stdio MCP server.

| Option | Meaning |
| --- | --- |
| `--collector <url>` | Collector URL (defaults to runtime state) |
| `--token <token>` | Bearer token (defaults to runtime state) |
| `--check` | Verify the collector and tool surface in memory, print JSON and exit |

`--check` exits non-zero when the collector is unreachable or the MCP surface is
invalid. It is a protocol check, not a model-driven client test.

### `stacknext skill`

| Command | Options | Purpose |
| --- | --- | --- |
| `skill path` | `--json` | Print the bundled skill directory and version |
| `skill install` | `--client opencode\|codex\|claude-code`, `--dir`, `--force`, `--json` | Copy the skill into a project |
| `skill uninstall` | `--client opencode\|codex\|claude-code`, `--dir`, `--yes`, `--json` | Preview or remove installed skill directories |

`skill uninstall` removes the whole `stacknext-debugging` directory, including
local edits. Without `--yes` it only prints the plan. See
[agent setup](/ai-agents/setup).

### `stacknext case`

Create and extend local, append-only investigation cases under
`.stacknext/cases`. Every command appends one event; no file is rewritten or
truncated. Titles and notes are length-capped and redacted. Directories are
`0700` and event files `0600`, with caps of 200 cases, 500 events per case and
100 evidence ids per case. Cases are never uploaded or auto-deleted.

| Command | Options | Purpose |
| --- | --- | --- |
| `case new` | `--title <text>` (required), `--hypothesis <text>`, `--evidence <kind>:<id>` (repeatable), `--session <id>`, `--json` | Create a case |
| `case add <id>` | `--evidence <kind>:<id>` (required), `--note <text>`, `--session <id>`, `--json` | Append evidence and an optional note |
| `case note <id>` | `--text <text>` (required), `--session <id>`, `--json` | Append a redacted note |
| `case close <id>` | `--status verified\|refuted\|abandoned`, `--session <id>`, `--json` | Append a terminal status |
| `case list` | `--json` | List cases newest first |
| `case show <id>` | `--json` | Show one folded case view |

Evidence kinds are `trace`, `error`, `diagnostic`, `comparison` and `snapshot`.
The collector reads cases at `GET /api/cases` and `GET /api/cases/:id`; MCP adds
read-only `list_cases` and `get_case` tools. The dashboard's `/cases` pages are
read-only.

### `stacknext verify`

Check one falsifiable claim against bounded captured evidence. No LLM, source
edit, SQL/EXPLAIN or time-window correlation is used; `unverifiable` is never a
pass.

```bash
stacknext verify --trace <id> --expect-status <code> [--json]
stacknext verify --route <route> --since <ms> --max-queries <n> [--json]
stacknext verify --route <route> --since <ms> --max-duration <ms> [--json]
stacknext verify --diagnostic <id> --expect-status <status> [--json]
stacknext verify --case <case-id> --json
```

| Option | Meaning |
| --- | --- |
| `--trace <id>` | 32-character trace id |
| `--route <route>` | Route path to sample |
| `--since <ms>` | Absolute epoch-millisecond timestamp; only requests at or after it are sampled |
| `--max-queries <n>` / `--max-duration <ms>` | The bound to check; exactly one with `--route` |
| `--diagnostic <id>` | Finding id (`diag-xxxxxxxx-xxxxxxxx`) |
| `--expect-status <code\|status>` | HTTP status for `--trace`, rule status for `--diagnostic` |
| `--case <id>` | Re-run the claim saved on a case and append one verification event |
| `--json` | Machine-readable result |

The result contains `claim`, `result`, `checks` (`predicate`, `expected`,
`observed`, `passed`, `evidence`), `revision` and `sampleSize`. At most 20
matching requests are sampled, newest first. `verified` correlation, null query
durations and missing evidence make a check `unverifiable`. Exit codes are `0`
supported, `1` contradicted and `2` unverifiable. Invalid arguments and
collector failures exit `1` with an error message. See
[agent workflows](/ai-agents/workflows).

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Command succeeded; `verify` result is `supported` |
| `1` | Command failed, `doctor` found a failing check, or `--fail-on` matched; `verify` result is `contradicted` |
| `2` | `verify` result is `unverifiable` or verification errored |
| `3` | `capture`'s child succeeded but the saved run is not `completed` |
| `130` | `capture` or `dev` received SIGINT |
| `143` | `capture` or `dev` received SIGTERM |

`capture` preserves the child command's exit code. Invalid ids and invalid
configuration fail before storage is read or network calls are made.
