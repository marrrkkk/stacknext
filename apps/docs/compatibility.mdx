StackNext targets Next.js App Router applications on the Node.js runtime. This
page separates combinations that were exercised during release validation from
combinations that are expected to work but were not part of the recorded matrix.

Last validation: **2026-11-03**.

## Supported surface

| Component | Supported |
| --- | --- |
| Next.js | 15 and 16, App Router only |
| Runtime | Node.js runtime |
| Node.js engine | `>=20.9.0` |
| Module format | ESM packages; CommonJS `require()` is not supported |
| Operating system | Linux (full e2e); Windows and macOS (package smoke in CI) |
| Package managers | npm and pnpm (validated); yarn and bun detection is best-effort |

The supported Next.js peer range is `>=15.0.0 <17`. A newer major prints a
warning in `stacknext init`; it is not treated as supported until it is added to
the validation matrix.

### Not supported

- Next.js Pages Router.
- The Edge runtime for instrumentation, Drizzle/Prisma adapters or the StackNext
  transport.
- Hosted or multi-user deployments. The collector binds to loopback and is
  designed for one developer machine.
- Parallel Playwright workers during a captured regression run.
- CommonJS consumers.
- Statistical significance or causal claims from regression comparisons.

## Next.js 15 and 16

Both major versions are exercised by the external consumer smoke test. Next.js
15 uses webpack for the instrumentation bundle; Next.js 16 uses Turbopack by
default. StackNext avoids the `node:` URL scheme in modules reachable from
`instrumentation.ts` so both bundlers can compile the hook. Applications that
add their own Edge middleware should still keep StackNext imports behind the
generated `NEXT_RUNTIME === 'nodejs'` guard.

## Regression testing

- Use one Playwright worker for captured runs. Parallel correlation is not
  verified.
- Use at least three samples per scenario.
- A baseline and candidate must come from matching environments to produce a
  conclusive comparison.
- Warm `/`, the project route and a database-heavy API route before capturing a
  baseline so one-time route-module spans do not appear on only one side.
- Comparison statuses are `improved`, `regressed`, `unchanged` and
  `inconclusive`. `inconclusive` is not a pass.

See [regression testing](/regression-testing) and
[CI integration](/ci-integration).

## Reporting a compatibility problem

Open an issue with the StackNext version, Node.js version, Next.js version,
package manager, OS, the output of `stacknext doctor --json` and the smallest
reproduction you can share. Remove tokens, URLs with query values, customer data
and any captured records before posting. Security reports follow
[SECURITY.md](https://github.com/marrrkkk/stacknext/blob/main/SECURITY.md), not
public issues.
